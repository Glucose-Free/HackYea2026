## 0. Fix first

1. **The demo shows the very leak the product is meant to stop.**
   - Stub (C): `deploy/stub_mcp/server.py:88-105` blocks contact only *after* AML knowledge. Contact first, then the AML summary, is never blocked. README demo steps 1 and 3 do exactly this, so Alice ends up with both.
   - Real engine (R): `block_aml_contact_data` and `block_aml_workplace_data` (`examples/aml.py:18-23`) join `aml_review` (subject `S…`) with `contact_data` (subject `C…`) on the same `?s`. They can never fire.
2. **Checkpoint 2 isn't integrated (C).** Nothing in `gateway/`, `deploy/` or `tests/` imports `policy_middleware`/`mcp_policy_server`. Compose runs the stub (`docker-compose.yml:31-36`). The README's `aml_contact` rule id exists only in the stub.
3. **The engine's trust model is incompatible with the contract (R).**
   - The engine is a stdio JSON-RPC loop with one `TrustedPrincipal` per process, and it ignores `_meta`. The contract wants streamable HTTP on :8001 with a per-call user from `_meta` (`mcp_policy_server.py:64-76, 192-202`).
   - Behind a shared gateway connection, every user would share one knowledge scope.
   - Decide the architecture first: a per-call gateway-attested principal, or a process per user.
4. **Refused prompts are replayed to the model (R).** `build_model_messages` (`gateway/agent/chat_agent.py:128-135`) forwards all past turns, including ones checkpoint 1 refused. "Please do what I asked above" then passes Jev and the model sees the injection. Assistant turns after the last user message are also forwarded unjudged (prefill injection).
5. **Fail-open config reload (R).** `CheckpointConfig.guards` defaults to `[]` (`gateway/config/model.py:30-31`). An empty or truncated `gateway.toml` (non-atomic editor save) hot-reloads with zero guards and every prompt is allowed. All-`monitor` or all-`on_error="allow"` configs are also accepted silently.
6. **The documented test command skips 92 of 222 tests (R).** `testpaths = ["tests"]` excludes `test_policy_middleware.py`, `test_mcp_policy_server.py` and `test_extensibility.py`. There is no CI at all (no `.github/`).
7. **Criteria gaps (from the PDF):**
   - no budget/cost/rate governance in the gateway;
   - no allowed-models list;
   - no redact outcome (only refuse);
   - no output check;
   - no deterministic PII/secret/known-exploit-signature guard;
   - the only real semantic guard needs a paid TypeSafe key (PDF §7 says no paid services). Consider a local model, e.g. via Ollama.
8. **The audit chain isn't tamper-evident against tail truncation (R).**
   - Truncate, restart, append → `intact=True`, and event ids continue with no gap.
   - Empty file → `intact=True`.
   - The hash is unkeyed SHA-256, so anyone with write access can rewrite and rehash the whole chain.
9. **Live config editing doesn't work in Docker (C).** The repo file is copied into the volume only once (`docker-compose.yml:21`), so editing `config/gateway.toml` does nothing after the first `up`. This contradicts the README.
10. **The image has never been built from the current code (TODO.md:9).** Demo secrets also apply silently via `${VAR:-demo-…}`.

## 1. Gateway: security and correctness

- **Plugin error during reload → 500 on every request, no audit line (R).**
  - `_reload` catches only specific exceptions (`gateway/config/provider.py:38,93`).
  - `get_current()` is called outside `Gateway.handle`'s try block (`core/gateway.py:59`).
  - The failed version isn't remembered, so it is rebuilt on every request.
- **MCP outage fails closed even for "hello" (R).** The session is opened and tools are listed before the first model turn (`agent/chat_agent.py:56-57`). Tools are also re-listed on every request.
- **No overall request deadline and no MCP read timeout (C).**
  - `tools.py:70,89` set no `read_timeout_seconds`, so the SDK default of 300 s applies.
  - Worst case is `(max_tool_rounds+1)` × 60 s model calls plus tool calls.
  - With `stream=true`, nothing is sent until the whole loop finishes.
- **Startup-only sections look hot-reloaded (C).** `chat_model.*`, `data_mcp.url` and `jev.*` are read once at startup (`bootstrap.py:63-77`). A reload still records a new `config_version` in the audit log.
- **`openai_compatible` with an empty `base_url` or `model` passes validation (R)** (`config/model.py:57-63`).
- **Tool-call `arguments` sent as an object kill the request (R).** `json.loads(dict)` raises (`agent/chat_model.py:82`). Accept dicts, and return parse errors to the model.
- **Duplicate identity headers are inconsistent (R).** The resolver takes the last `x-openwebui-user-id` while `headers.get` takes the first. Reject duplicates.
- **Header identity can be spoofed by anyone holding the API key (C, TODO).**
- **Public `/docs`, `/redoc` and `/openapi.json` (R)** expose the admin surface (`app.py:31`).
- **Non-ASCII token → 500 in `compare_digest` (R, TODO).**
  - `?token=` leaks into logs and history (TODO).
  - The Bearer scheme match is case-sensitive (`api/dependencies.py:17`).
- **Secrets appear in `repr(components)`** (`components.py:14,16`). Use `SecretStr` or `field(repr=False)`.
- **NaN or out-of-range Jev probability → allow** (`guards/builtin/jev_semantic.py:94-110`, unverified). Treat it as an error so `on_error` applies.
- **Guard `detail` can overwrite the audited `decision`, `mode` or `errored`** (`core/gateway.py:127-135`). Nest it under `guard_detail`.
- **A duplicate guard entry-point name silently replaces a built-in** (`guards/registry.py:30-34`).
- **No size limits** on message count or length, and no cap on tool calls per turn (`api/openai_compat.py:50-54`, `chat_agent.py:65`). This is a cost-abuse vector.
- **Every MCP `isError` counts as a checkpoint-2 denial**, and tool names aren't checked against the listed tools (TODO, `tools.py:92`, `chat_agent.py:67`).
- **Indirect prompt injection via tool results** (TODO).
- **Forged client history** (TODO).
- **OpenAI-compat gaps:**
  - no `usage`;
  - errors use the FastAPI `{"detail"}` shape, not `{"error":{…}}`;
  - `n`, `model` and `response_format` are ignored silently;
  - no keep-alives while streaming.
- **Blocking I/O on the event loop.**
  - The config file is read and SHA-256-hashed on every request (`config/store.py:63-64`); check mtime first.
  - Audit append does sync I/O under a `threading.Lock` (`core/gateway.py:97-102`).
  - The audit write is fail-open: a swallowed exception means the request is answered without being audited.
- **Reload reads the file twice (TOCTOU, `provider.py:81,91`).**
- **`FileConfigStore` history issues** (`config/store.py`):
  - re-archiving rewrites the file and breaks mtime ordering;
  - the active version isn't in history;
  - no fsync before `os.replace`;
  - `activate` doesn't verify the hash.
- **Stub Jev is trivially bypassed.** An extra space or a synonym gets through (`jev/client.py:13-21`). It is the default demo path.
- **Stub MCP doesn't follow the contract.**
  - It falls back to a shared `unknown_user` bucket where §3 says deny (`stub_mcp/server.py:22,52-56`).
  - It ignores `customer_id` in decisions and defaults it to `CUST-17`.

## 2. Policy engine (`policy_middleware.py`, `mcp_policy_server.py`, `examples/`)

- **Permanent per-user lockout as history grows (R).**
  - An unrestricted `ValueDomain()` expands to every known constant (`:652`).
  - After about 5k calls every call returns `inference_failed`, including for new IDs.
  - The limits are hard-coded (`:239-240, 710`) and history never expires.
  - A looping, prompt-injected model can trigger this deliberately.
- **Global SQLite write lock held during the backend read (R).**
  - `BEGIN IMMEDIATE` wraps `execute()`, which has no timeout (`:395, 690-749`).
  - Another tenant waited 2.7 s behind a 3 s executor. Reads also take `IMMEDIATE`.
  - Fix: WAL mode, deferred reads, per-scope locking and an executor timeout.
- **Replays ignore later policy changes and aren't audited (R).** A cached `reply_json` with private data is returned after the rule was tightened (`:691-701`).
- **Entity IDs aren't canonicalised (R).** `S17` and `S017` are different constants (`examples/aml.py:27-30`). This becomes a bypass if the backend normalises them.
- **Post-execution validation refusals are a data oracle (R).** 100 accounts → allow, 101 → block (`examples/aml.py:90-109`).
- **A value starting with `?` collides with the variable syntax (R).** Company `?acme` blocks the whole response (`:63-64, 111-113`).
- **`Proof.rule_ids` is filled from `DatalogRule.name`, not `rule_id`** (`:224`).
- **`"security_admin"` is hard-coded in the "domain-free" core** (`:419`). Audit is scoped per tenant only, so an admin of one dataset sees every dataset (R).
- **`TrustedPrincipal` is trusted by convention only.** `dataclasses.replace` forges it (`:72-82`).
- **Rate limit and ID cap are per process/connection** and reset on reconnect. Rejected arguments consume a token but are never audited (`mcp_policy_server.py:81-83, 112, 188-191`).
- **KnowledgeStore setup** (`:367-388`):
  - `executescript` implicitly commits, so the legacy check isn't atomic;
  - `chmod 0600` runs after the file is created;
  - journal files aren't covered.
- **Denials carry no `checkpoint_steps`.** Rate-limit, bad-argument and policy denials share one shape (`mcp_policy_server.py:171-199`).
- **Catalog differs from the contract.** It lists 7 tools, not 5. Tools take required ID arguments, and the fact names differ (`aml_review` vs `aml_flag`) (`examples/aml.py:39-70`).
- **JSON-RPC nits (R):**
  - an extra top-level member gives -32602 instead of -32600 (`:122`);
  - `initialize` rejects unknown params (`:143`);
  - `redirect_stdout` is process-wide (`:196, 262`);
  - `idempotentHint: False` on read-only tools.
- **Performance (R).** Naive, not semi-naive, fixpoint (`:247-290`). Latency is 0.7 ms → 113 ms at 4k facts, so cumulative cost is quadratic. The policy JSON is re-parsed and the full history reloaded inside the lock on every call (`:709, 714`).
- **Over-blocking by design.** Any rule that equates two unknowns always blocks (`test_extensibility.py:569`). The postflight Datalog check is unreachable given a sound preflight. Keep it as defence in depth, but comment why.

## 3. Audit subsystem and dashboard

- **No XSS found.** The dashboard only uses `textContent`, and `report.py` escapes. Missing: a CSP and security headers (`frame-ancestors`, `no-referrer`, `no-store`). Three inline `setAttribute("style")` calls would need changing for a strict CSP (`dashboard.js:426,610,943`).
- **One invalid UTF-8 byte in the log stops the gateway from starting (R).** Every admin endpoint then returns 500 (`audit/log.py:66,121-125`).
- **Malformed events slip past `is_readable_event` → 500s (R).** A non-dict `user`, `fetches` or `detail`, or a non-numeric `step_id` (`audit/query.py:183-268`, `trace.py:568`). Parse each event once into a typed record.
- **Unicode-digit cursor `"²"` → 500 (R)** (`query.py:263-268`).
- **Offset pagination duplicates rows under live traffic.** Auto-refresh runs every 15 s (`query.py:305-310`). Use a keyset cursor.
- **`loadRequestsView` and `loadMoreRequests` have no stale-response guard** (`dashboard.js:724-752`).
- **Users with no fetch attempts are invisible** in the user list and filters (`query.py:287-303`).
- **Views filter on different timestamps.** Request lists use event `ts`; fetch totals use step `started_at` (`query.py:244` vs `192/336`). Default ranges also differ: all-time vs 24 h (`admin.py:272-304`).
- **The audit log is a PII store behind one shared token.** It holds full prompts, replies and tool args. `/audit` dumps everything unpaginated (`api/audit.py:24-26`). There is no retention policy.
- **No rate limit on token attempts.**
- **`/audit/verify` is public and leaks the event count.** Make that a deliberate decision.
- **Durability gaps:**
  - no fsync;
  - `_count` is incremented before the write;
  - a partial last line breaks the chain permanently, with no recovery path;
  - readers don't take the lock (TODO);
  - ids repeat after a corrupt line (TODO);
  - single worker only (TODO).
- **Canonical JSON allows NaN.** Use `allow_nan=False` or JCS (`log.py:56`).
- **Every query re-reads the whole file (R).** One Requests refresh is about 5 full reads, about 180 ms at 675 events, and it grows linearly (TODO "Scale"). Cache by mtime and size, or keep an incremental projection.
- **Dashboard bugs and UX:**
  - uneven y-axis ticks: `0,1,2,4,5,6` (R, `dashboard.js:352-363`);
  - an unknown status crashes the list (`:869-872`);
  - sign-out leaves prompts in the DOM;
  - when `localStorage` writes fail, the in-memory token is ignored;
  - day buckets are UTC.
- **Accessibility:**
  - contrast fails WCAG AA: muted text 3.38:1, red badge 2.49:1 (`dashboard.css:149,155,251`);
  - no focus trap or focus return in the trace dialog;
  - rows don't respond to Space;
  - `outline: none`;
  - the chart uses colour only;
  - no light theme;
  - inconsistent breakpoints.
- **Report naming.** The "Recent denied requests" heading also includes failed-closed requests. The `detail` field is shown as a Python repr (`report.py:403-438`).
- **Checkpoint-1 refusals are counted as "fetch attempts"** (`query.py:184-186`).
- **Seeder (`deploy/demo_audit/seed_audit_log.py`):**
  - it duplicates `AuditLog.append`'s sealing logic (`:270-280`), so extract `seal_event()`;
  - it isn't reproducible despite `RANDOM_SEED`;
  - timestamps can be up to 6 s in the future;
  - it can fork a live chain;
  - it imports constants from the stub;
  - seeded user ids (`u-alice`) may not match Open WebUI's UUIDs (unverified).
- **`seed_users.py`** treats any 400 as "already exists", and a missing env var gives a raw `KeyError`.
